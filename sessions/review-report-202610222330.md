### Findings

1. **Blocking, fixed before it could mislead (probe design).** `portraits.test.js` is red by
   design until portraits are downloaded (the "at least one portrait" floor), so a probe running
   the whole file would count every mutation as caught. The three probes run only the
   "portrait credit rules" tests, after a clean control run.
2. **Blocking, fixed (finder).** Three wrong identities came back on the way. A Commons name search
   for Donald Hebb returned Donald Rumsfeld, Tom Brown returned a 1934 film actor, and Ronald
   Williams returned another Williams. The Wikipedia lead image for Hebb was a diagram of brain
   lobes. Search hits now need every name part plus a research field in their description.
   Wikipedia lead images must be photos named after the person. After review, no search result is
   on the list; all 14 candidates are the persons' own Wikidata images.
3. **Should-fix, fixed (finder).** Wikimedia rate limits (HTTP 429, missing `query` in replies)
   crashed early runs. The finder now spaces requests one second apart, backs off on 429/503
   honouring `Retry-After`, and treats an empty reply as no result.
4. **Should-fix, fixed (approval list).** Six Commons links in the hand-built table had
   unencoded parentheses, which can break a Markdown link. All 14 now equal the API's URLs
   (checked by script).
5. **Raised for the owner, not fixed:** the Rosenblatt photo's free licence is doubtful (unknown
   1950 author, CC BY-SA 4.0 claimed by the uploader), and the Sutskever file is too small for a
   face at card size. Both are listed as "advised against" with the reason.
